# ADR 0004 — svg-diagram で会議の議論を図解する

- Status: Proposed
- 日付: 2026-11-24
- 関連: [ADR 0001 — 議論グラフ](0001-discussion-graph.md)、[ADR 0002 — Windows E2E](0002-e2e-scripted-backends.md)

## 背景

Meetingram の主要な成果物は、それまでの会議内容を俯瞰できる図。現行の議論グラフは発話と議題・案・賛否などの構造を保持し、録音中と履歴のアウトラインが同じグラフを読む。描画は ADR 0001 が後続 ADR に委ねた。今回の到達点は、Meetingram の画面で図を見て、その SVG を保存できること。

## owner の決定

| 問い | 決定または提案 |
| --- | --- |
| 最優先の成果物 | svg-diagram による会議内容の図解（2026-11-24） |
| 表示の起点と最初の図種 | 提案。録音中と履歴で、利用者が操作して表示・更新できる議論マップを作る |
| 初回の配布方式 | 提案。svg-diagram のブラウザ向けコードを Windows アプリに組み込む |

## 選択肢

- **A. 既存の WebView2 で svg-diagram を動かす。** svg-diagram のブラウザ用エントリーをビルド時に組み込む。WebView の文字計測を使える。描画負荷と静的アセットの組み込みを検証する必要がある。
- **B. Node と svg-diagram のレンダラーを同梱する。** 描画負荷を別プロセスに分離できる。配布形式、依存ライブラリ、Windows でのフォント解決を追加で扱う。
- **C. 編集用の TypeScript を書き出す。** 実装は小さい。図を見る操作は外部の環境構築とビルドに依存する。

## 提案する決定

A を採用する。対象は既存の議論グラフ画面を持つ Windows。svg-diagram 0.9.0 の `svg-diagram/browser` は `diagram`、`mindmap`、`renderInBrowser`、`svgMeasurer` を公開する。Node 専用依存に到達しない入口であることを既存のバンドルテストが検証している。[ブラウザ用公開 API](https://github.com/cuzic/svg-diagram/blob/v0.9.0/lib/web.ts)

Meetingram が固定の TypeScript アダプターを所有する。ビルド時にブラウザ用の静的 JS にバンドルしてデスクトップ実行ファイルのアセットに組み込み、WebView2 で呼び出す。現在の単一 EXE 配布を維持し、利用時の Node、CLI、追加プロセス、オンライン取得を不要にする。初期候補は公開パッケージの svg-diagram 0.9.0。レンダラー用ディレクトリのロックファイルに svg-diagram と esbuild を固定する。初回の採用時に npm 配布物のブラウザ向けコードを v0.9.0 タグのビルドと照合する。ロックの integrity を使い、依存のインストールは `npm ci --ignore-scripts` とする。esbuild の実行に必要なプラットフォーム用パッケージがこの条件で揃うことも検証する。生成 JS を同じ変更に含め、Linux の app-build CI で固定版 Node を使って再生成し差分を検査する。通常の Cargo ビルドは Node を要求しない。Rust 側で `include_str!` した IIFE を WebView の文書ごとに一度だけ初期化し、単一の名前空間に描画関数を登録する。初期化は同時要求で共有し、画面の再読み込み時には再初期化する。描画ごとに実行する eval は固定の短い呼び出しだけとし、入力は `send`、結果は `join` で渡す。配布物にはライセンス表示を含める。

### アダプターの契約

入力は `version: 1` と `root: {label, sub?, children?}` を持つ構造化 JSON。Rust 側で投影と入力上限を適用し、Dioxus の構造化メッセージで固定の JS に渡す。ラベルの JavaScript 文字列への埋め込み、任意の Markdown、URL、画像、DSL オプションの受け取りは設計に含めない。レンダラーは`appearance: "light"` と固定テーマ・レイアウトの `mindmap` を作って `renderInBrowser` に渡し、成功時は SVG と寸法、失敗時は会議内容を含まない分類コードを返す。失敗コードは `invalid_input`、`limit_exceeded`、`render_failed`、`invalid_svg`。JS は例外を捕捉し、例外のメッセージ・スタック、verdict の説明や個々のラベルを結果や console に出さない。verdict のエラーは `render_failed`、警告だけなら SVG と固定の注意表示フラグを返す。XML の不整形式は `invalid_svg`。

### 図に出す情報

- 「議論の全体像」を単一ルートに置き、既存アウトラインと同じ順序で議題・子議題をたどる。既定は全議題。横方向の片側レイアウトで、個別議題を選ぶとその枝を表示する。案の賛否はラベルでも示し、決定や未確定の区別も文字で示す。見出しに描画時点を表示する。
- 枠は種類で塗り分ける（svg-diagram の tone）。決定は `solid`、宿題は `accent`、未回答の問いは `danger`、賛成の理由は `new`、反対の理由は `removed`。案・回答のある問い・根は指定しない。状態の語は問いと宿題だけに出し、問いは生きた決定が付いていれば「決定済み」、未回答なら「未回答」と、辺から導く。長いラベルは文節で折る（`wrap: 'bunsetsu-soft'`）。SVG の許可リストには `stroke-dasharray`（`数,数` の形だけ）を足す。
- 人が却下した項目や置換済みの項目は除く。低確信度の項目に確認が必要であることを示す。別の枝にも現れる項目は「参照」付きの葉として表示し、子は展開しない。接続のない項目は「未整理」に残す。既存のアウトラインから根拠の発話を確認できる。
- 初回の図種は議論マップとする。因果関係や前提条件を推定する CRT・対立解消図と、会議横断の図解は別途設計する。

### 操作と更新

- 会議中のアウトラインと履歴のセッションに「議論を図解」を置く。その時点で保存済みのグラフを表示する。保存済みの項目がない間は理由を表示する。
- コア v0.13.0 の `GraphStore::load_graph` は SQLite の同一トランザクションで `Graph.rev` を取得する。アプリ側の既存 `db()` 経由の読み取りを再利用し、読み取りの前後で `status()` の世代と再構築状態を照合する。再構築中または世代が変わった値は返さない。LLM 呼び出し中も保持され得る実行ロックは取得しない。取得したセッション ID・世代・リビジョン・選択範囲と、単調増加する要求番号を描画要求に付ける。表示先と要求番号が変わった完了、および同じセッションでも世代が変わった完了を捨てる。同じ世代でリビジョンが進んだ場合は、描画したリビジョンを明示し「更新あり」を出す。現行の世代はアプリが再構築を判定する実行時の値で、SQLite スキーマに追加しない。
- 描画中の追加操作は最新の1件にまとめる。表示を閉じた場合は返ってきた結果を破棄し、計測 DOM を取り除く。WebView 上で実行中の同期レイアウトは即時中断できないため、入力を制限し、性能試験で UI 応答を測る。
- 図を拡大して読めるようにし、保存先を選んで表示中の SVG を保存する。上限を超える場合は、議題単位で範囲を選び直せるようにし、選択範囲を図にも明示する。自動で一部の項目を消さない。

### フォントと会議データ

- WebView2 の `document.fonts.ready` を待ち、表示されているホストで `svgMeasurer` を使う。終了時には `dispose` する。計測と WebView 内表示のフォントスタックを揃え、初版の SVG にはフォントを埋め込まない。別の環境で開く場合の代替フォントによる見え方は検証対象とする。
- グラフの項目ラベルや関係も会議内容として扱う。描画はオフラインで、音声、発話原文、認証情報をアダプターに渡さない。ラベル・図の内容をログ、例外表示、永続キャッシュへ書かない。既存の SQLite、イベント形式、LLM 設定を再利用する。
- Rust が戻り値のサイズと UTF-8 を確認し、DTD・実体宣言を無効にした XML パーサーで要素・属性を許可リスト検査する。許可リストは固定版の合成図 fixture に基づく。スクリプト、イベント属性、外部参照と `foreignObject` を拒否する。内部 CSS を使う場合は CSS パーサーで生成器のセレクターと宣言だけを許可する。CSS エスケープ、@ 規則、`expression()`、外部 URL と未知の関数値を拒否する。ローカル参照は同じ文書の既存 ID に限定する。合格した UTF-8 バイト列を Rust が保持し、同じバイト列をプレビューの `<img>` 用に Base64 の SVG data URL に変換し、保存時はそのバイト列を直接書き出す。

## 先行検証と暫定基準

Windows x64 の配布ビルドとクリーンな Windows 環境で実施する。代表入力は30項目、上限入力は100表示項目（参照を含む）、深さ16、1ラベル240文字、入力128 KiB、出力1 MiB。描画は同時に1件。各サイズ10回の計測で、操作から画像の表示まで30項目は1秒以内、100項目は3秒以内を9回以上満たす。PerformanceObserver の longtask を記録し、描画中の最長メインスレッドタスクが500 ms以下であることと、録音ボタンの操作が500 ms以内に受理されることを別々に確認する。いずれかを超える場合は初版の表示項目上限を引き下げ、再測定する。Worker 化は計測精度を別途検証してから判断する。生成 JS のサイズと初回の解析・初期化時間、長い日本語ラベルのはみ出し・フォント代替、検証エラーの発生率も記録する。性能の合否はクリーンな Windows 実機で判定する。機能回帰は既存の録画付き `windows-e2e.yml` に描画シナリオを追加して検知し、実装のレビュー時に成果物で合否を確認する。必須 CI チェックの設定は維持する。値は提案であり、実測は未実施。

## Claude Opus レビュー

2026-11-24 の初回レビューは要修正。以下は Node 同梱案への指摘。r2 でブラウザ用 API に切り替え、配布・入力契約・フォントの検証方針を改めた。

- 現行の Windows 配布は単一 EXE。同梱に必要なランタイムとネイティブ依存の収録方法、サイズ、ライセンス、更新方法を検証する。
- 現行の svg-diagram CLI は TypeScript を入力に取る。提案の JSON 標準入力は新しいアダプターの契約であり、対応版、入出力、異常終了時の扱い、アダプターを置くリポジトリを決める。
- Windows の日本語フォントの解決方法を検証する。描画時の計測と WebView・保存後の SVG の表示で、長いラベルがはみ出さないことを確認する。

追加の指摘は、子プロセスの環境・設定の隔離、測定規模と合格閾値、世代とリビジョンによる完了結果の照合、複数議題と参照ノードの投影方法。

## 追加レビュー第1回の対応

Opus はブラウザ用 API の存在を確認し、ブロッカーなし・要修正と判定した。r3 でビルド、状態の取得、XML/CSS 検証、エラー分類とログ、WebView の応答時間を具体化した。Windows の実機確認は配布の合格条件とし、既存の Windows E2E のマージ条件はこの ADR では変更しない。

## 追加レビュー第2回の対応

Opus はブロッカーなし・要修正と判定した。r4 で WebView2 検査を載せる既存ジョブと確認経路、依存の供給元と再現ビルド、文書ごとの初期化、SVG のプレビュー方式を明記した。暫定上限とフォントの表示品質は実測して判断する。

## 実装の分割と合格条件

| 順 | repo | 作業 | 合格条件 |
| --- | --- | --- | --- |
| 1 | Meetingram | 投影とブラウザ用アダプターの検証 | Linux で投影・上限・却下・参照の単体テストを行う。録画付き Windows E2E に描画シナリオを追加し、WebView2 で日本語を含む合成グラフをオフラインで描画した結果を成果物で確認する。議題、案、賛否、決定、未整理、参照が読み取れる。空、長文、大規模、特殊文字、拒否すべき XML/CSS、例外時に合成ラベルがログ・診断応答に含まれないことを確認する |
| 2 | Meetingram | 録音中・履歴から表示と保存 | 合成会議で、アプリから図を開き、議論を追加して更新し、保存した SVG を開ける。別会議や再構築前の図が混ざらない。失敗しても録音中の処理は続く |
| 3 | Meetingram | 配布と利用者評価 | 新規セットアップした Windows に配布物を置き、追加インストールなしで図を表示する。合成会議にあらかじめ設定した決定・反対理由・未解決の問いを、利用者が図とアウトラインを使って各1件特定できることを記録する |
