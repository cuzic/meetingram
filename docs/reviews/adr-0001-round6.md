## Findings

### P1（Minor）: 要約の codex の打ち切りは、拒否リストで事後に検知するだけ。codex の hooks がプライバシーに無い
- 根拠:
  - §2 は「`item.started` の command・mcp_tool_call・web_search など」が出たら止める。型を挙げる拒否リストなので、
    機能の無効化（未知のキーは黙って無視される）と同じく、新しい型（`functions.exec` の code mode、`collaboration.*` のサブエージェントなど）を取りこぼしうる。
    サブエージェントのイベントが親の `--json` に出るかも確かめていない。
  - `item.started` を受けた時点では、ツールの呼び出しは始まっている。打ち切りでできるのは、結果を使わないことと、次の呼び出しを止めることだけ。
    外部への送信そのものは防げない。外部に出しうる道具（`apps`、web 検索）を確実に外せるのは、無効化の一覧と `web_search="disabled"` の側だけ。
  - 要約の codex では、`hooks` の機能（既定で有効）も利用者の codex の hooks も残るので、hooks が本文を受け取りうる。§「影響」のプライバシーには、claude の分しか書いていない。
- 修正案: 打ち切りは許可リストで決める。`thread.*`、`turn.*`、`item.*` の `agent_message` と `reasoning` 以外の item が出たら打ち切る。
  許可する型は、実 CLI の正常な要約のイベントから集め、タスク 4 の README の手作業の確認に入れる。
  §2 には「打ち切りは事後の検知で、外部への送信は無効化の一覧で防ぐ」と書く。プライバシーには「codex CLI の要約でも、利用者の hooks が本文を受け取りうる」と足す。

### P2（Minor）: タスク 4 の受け入れ条件の文言が古い。起動の条件のテストの置き場所
- 根拠: タスク 4 に「codex の 3 つのツールの無効化を含む」が残っている。§2 は 11 の `features` と `web_search` と `--json` になった。
  「グラフの起動の条件が codex CLI で偽になるテスト」はタスク 4（core）にあるが、起動の条件はアプリの consumer（タスク 5）が判断する。
- 修正案: タスク 4 は「§2 の無効化の一覧全部と `--json`」を固定するテストにする。
  起動の条件のテストは、core に判定の関数を置くならタスク 4、置かないならタスク 5 の受け入れ条件に移す。

### P3（Minor）: S2 の「誤った `merge`」の判定の基準と、再現率の歯止め
- 根拠: 整理の後のグラフでは `from` が `merged` になり、正解との対応付けから外れる。だから「`from` と `into` が正解の別々のノードに対応する」は、
  整理の前の保存したグラフでの対応付けで判定しないと決まらない。
  r7 は再現率の条件を外したので、正解に対応するノードを、正解に対応しないノードへ `merge` する場合（再現率だけが下がる）は、どの条件にも引っかからない。
  A の sonnet は強める前でも正解の 1.2〜1.5 倍なので、25% 減らすと正解の数を下回りうる。過剰な `merge` を止める歯止めが要る。
- 修正案: 誤った `merge` は、保存した整理の前のグラフの対応付けで判定すると書く。「対応ありのノードを対応なしのノードへ `merge` した組」も誤りに数えるか、
  再現率（3 回の中央値）が強める前より下がらないことを条件に足す。

### P4（Minor）: `CREATE_SUSPENDED` で起動した後の再開の方法が書かれていない
- 根拠: `std` と `tokio` の `Child` は、主スレッドのハンドルを返さない。`creation_flags(CREATE_SUSPENDED)` で起動すると、そのままでは再開できない。
- 修正案: 再開の方法を 1 つに決めて書く（`NtResumeProcess`、Toolhelp32 で主スレッドを探して `ResumeThread`、または `windows` crate で `CreateProcessW` を直接呼ぶ）。
  タスク 4 の Windows の CI の「`.cmd` 経由の孫がタイムアウトで止まる」で、この経路を通す。
