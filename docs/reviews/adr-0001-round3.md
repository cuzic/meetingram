## Findings

### R1（Minor）: 再文字起こしの後の抽出と作り直しに、`graph_enabled` と起動の条件が書かれていない
- 根拠:
  - §3 の「起動の条件」は録音の開始時の consumer だけにかかる。「再文字起こしの後」は「取り込みと増分の抽出を 1 回走らせる」とだけあり、`graph_enabled` が無効なとき・バックエンドが無いときの扱いが無い。
    書いてあるとおりに作ると、グラフを無効にした人の文字起こしが、再文字起こしのたびに LLM に送られる。
  - 録音時にグラフを作らなかったセッション（当時は無効・キーが無い）では、`id > 0` から全部を抽出することになり、確認の画面の無い作り直しと同じになる。
  - 作り直しは利用者がボタンを押すので送信の同意はあるが、`graph_enabled` が無効なときにボタンを出すかも決まっていない。
- 修正案: 「再文字起こしの後」は、`graph_enabled` が有効で、バックエンドを組み立てられて、そのセッションに既にグラフがあるときだけ、と書く。
  作り直しのボタンは `graph_enabled` が無効なら出さない（または押したときに送信先を示して確認する）。タスク 5 に「無効なら再文字起こしの後に何も送らない」テストを足す。

### R2（Minor）: 逐次の検証の例文が、表の規則と食い違う
- 根拠: §2 の「`merge A→B` の後の `merge B→C` は、B が `merged` なので落ちる」。
  表の適用では、`merge A→B` で `merged` になるのは `from` の A で、`into` の B は `merged` にならない。`merge B→C` は通り、表の「`merged_into = from` のノードも `into` に向け直す」で A も C を指す。
  タスク 2 は「表の 1 行ごとに単体テスト」なので、例文どおりにテストを書くと規則とぶつかる。
- 修正案: 例を「`merge A→B` の後の `merge A→C` は、A が `merged` なので落ちる。`merge B→C` は通り、A の `merged_into` も C に向け直す」に直す。

### R3（Minor）: 入力の枠の内訳に、システムプロンプトと参照用の発話が入っていない
- 根拠: §2 は文脈に 1/3、1 件の発話に 1/3 を割るが、システムプロンプト（見積もり 1.5k トークン）と「参照用の直前の 3 発話」の枠が無い。
  参照用の発話は切り詰めの対象でもないので、直前に長い発話が続くと、入力が上限を超える。
  タスク 4 では上限を超えるとエラーになるので、その回は失敗する。同じ発話で 3 回失敗すると流し切りが止まる（会議中も抽出が止まる）。
- 修正案: 参照用の発話にも同じ切り詰め（例: 1 件 200 文字）をかける。組み立ての関数が「システム＋文脈＋参照＋新しい発話 ≤ 上限」を必ず守ると §2 に書く。
  タスク 2 に、長い参照用の発話でも上限を超えないテストを足す。

### R4（Minor）: 新しく出てきた UI と再起動の扱いが、タスクの受け入れ条件に無い
- 根拠:
  - §3 の「未抽出 N 件」の表示と「続きを抽出」のボタンが、タスク 6・7 のどちらにも無い。
  - 流し切りが連続失敗で止まったときに、整理（§3 の 3）を走らせるかが無い。
  - 流し切りの途中でアプリを終了した場合、次に起動しても再開する経路が無い。`extracted_rev IS NULL` の行や、まだ取り込んでいない確定行が残るだけ。
  - 再文字起こしの後の抽出のテストがタスク 5 に無い。
- 修正案:
  - タスク 6 に「未抽出・未取り込みの発話の件数と『続きを抽出』（`id > max(row_id)` と `extracted_rev IS NULL` を流し切る）」を足し、再起動の後もこの件数で気づけるようにする。
  - 流し切りが止まったら整理はしないと §3 に書く。
  - タスク 5 に再文字起こしの後の抽出のテストを足す。
