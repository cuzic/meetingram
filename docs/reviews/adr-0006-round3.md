## Findings

### M1（Major・ADR 0006 §5）: LLM が返した `d`・`d2` の本文が切られず、120 を超えると描けない
- 根拠: 表の後の注（`docs/adr/0006-conflict-cloud.md:221`）は「『各要素』と『根拠』の行は D・D2 には当てない」とする。
  「D・D2」の行（215 行目）が 116 単位で切るのは、本文が無い・空のときに使う position の本文だけ。LLM が返した `d`・`d2` の本文には、どの行も長さの上限を当てない。
  system は「短く言い直したもの」と頼むだけなので、LLM が 121 単位以上を返すと、その行は保存される。しかし svg-diagram の `cloud` の `d`・`d2`
  （`maxLength: 120`）を超えるので、開くたびに描画が失敗する（round 1 の M2、round 2 の M1 と同じ種類）。
- 修正案: 「D・D2」の行に「LLM の本文も 116 単位で切る（サロゲートペアを分けない）」を足す。D・D2 は推測の印を付けないので 120 でもよいが、
  ほかの要素と同じ 116 にすると規則が 1 つで済む。タスク 1 の受け入れ条件に「長すぎる `d`」のテストを足す。
